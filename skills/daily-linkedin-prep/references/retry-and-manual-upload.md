# Recovery and manual-upload handoff — October 1 user correction

Read this before handling any browser/upload failure or Notion handoff. This later explicit user correction overrides September 29 done-only tracking for the narrow manual-upload exception below. Never submit applications.

## Exhaust applicable supported recovery, then try another job

An error is not a run stop. Checkpoint the attempted operation and exact error, identifying its source (browser runtime, Edge connection/CDP, selector layer, employer validation, or permissions). Re-observe the existing page/attachment before replaying an action whose outcome is uncertain.

For transient failures, try each applicable supported recovery path: fresh page evidence and corrected locator; documented DOM or screenshot controls when semantic selectors fail; reacquire a stale tab from the existing browser binding; documented connection recovery only when appropriate; and the documented file-chooser flow or permitted native picker fallback for uploads. Catch asynchronous chooser rejection so it does not unnecessarily reset the session. Verify results after each attempt. Record each path's outcome, or why it is unavailable, unsafe, already exhausted, or not applicable. Do not cycle identical failed actions indefinitely, bypass a denial, change permissions, duplicate a form, or retry an uncertain upload without inspecting its result.

Verified October 1 recovery: a hidden required file-input click timed out waiting for the chooser (runtime reported 3000 ms despite 10000 ms requested). The exact application was then brought to the foreground using supported native tab controls, and the associated visible Upload File button was clicked with a fresh chooser listener. The chooser and exact-PDF upload succeeded. When applicable, try this changed foreground/visible-control path before manual-upload handoff. Inspect current tab and attachment first, never reload a filled form merely to focus it, and do not infer that every chooser timeout has this cause. DOM email values may be masked even when filled; verify by screenshot before repeating or declaring failure.

After employer-local recovery is exhausted, finish all other accessible supported fields and non-final steps, preserve the draft, checkpoint, release its claim, and attempt the next eligible job. A failed upload must not prevent further fields, screening, or another application. If upload is required to reach later pages, record the exact page barrier; never claim inaccessible fields were completed.

Before declaring a run-wide browser blocker, attempt a bounded startup/read/action on a different eligible job's actual application, if any is available and duplicate checks permit it, plus an independent research navigation. Log current evidence from both and the supported recovery paths tried. A failed read of the original tab, an old failure, or one failed chooser is insufficient. If a shared dependency prevents even opening the next application, record that attempted next-job failure. Continue any useful permitted offline work. Stop only when no useful permitted progress remains, the target is met, the search is positively exhausted, or the user stops the run.

## Manual résumé upload handoff

When upload remains unsuccessful after applicable recovery, finish the application to the best supported extent and log it in Notion even though it is not `done`. Require verified job identity, all accessible supported fields filled, a distinct preserved application tab, an existing QA-passed job-specific PDF with hash, and an honest record that attachment is missing or unverified. Unknown personal answers remain blank and listed. If fresh live verification is unavailable, retain a pending tracking receipt and mark verification uncertainty rather than claim the form is currently verified.

Parent writes one per-job receipt under `RUN/manual-upload-handoffs/JOB_ID.json`, containing run/job/ATS identity, employer/title, review URL/tab, form evidence, PDF absolute path/hash/manifest, upload attempts and errors, inaccessible later steps, unknown questions, and `attachment_verified: false`. Only the parent produces these receipts after reviewing evidence. Keep ledger/queue status `blocked`; do not falsify upload gates or call queue `complete`. Release the application claim and continue the next job. Existing strict helper semantics remain unchanged.

The Notion recorder consumes both verified `done` receipts and these parent-issued manual-upload receipts. For a manual-upload receipt, deduplicate and create/update the application row using the existing authorized `Preparation Blocked` status; prominently put **Needs résumé upload — fields filled to best supported extent** in the row body. Include the exact local PDF path, hash, review URL, errors, inaccessible steps and outstanding questions. Leave Application Date blank. Never mark submitted or downgrade submitted/interview/rejected outcomes. No résumé upload to Notion and no private candidate answers. Reopen and verify the saved row; record its URL/result in `notion-tracking.json` with `handoff_kind: manual_upload`. Pending/uncertain Notion writes must be reconciled before retry.

The recorder is the sole tracking writer. Because the queue helper deliberately only claims `done` entries, manual-upload receipts are dispatched directly by the parent to this worker, not forced through `claim --role notion` or `note`. Browser batches still run in the parent session under the exclusive parent-maintenance discovery lease. Do not modify queue JSON or forge helper completion. Track manual handoff status separately in `notion-tracking.json`.

Reports must link every manual-upload draft, Notion row (or pending write), and exact local PDF. Show separate totals for fully ready, prepared with personal questions, and fields-filled/manual-upload-needed. Manual-upload drafts are not fully ready or strict verified-prepared target completions; explain their useful completed work without concealing missing attachments. A PDF alone, blank form, queued listing, or unrelated technical failure does not qualify for this exception.
