# Private candidate context — local setup template

Populate this template privately with applicant-approved facts and exact confirmed answers, and supply the full text as `LINKEDIN_CANDIDATE_CONTEXT`, or provision candidate-context.md in the configured private directory outside the repository. Do not run applications using placeholders. Keep `master-resume.txt` as a separate private baseline.

## Precedence and maintenance

Newer explicit user answers override older answers only for the same question and scope. Use original message dates rather than file modification dates. Employer-specific salary, policy acknowledgment, work-history and eligibility answers retain that scope; time-bound answers retain their as-of date. Preserve old values as superseded history and keep unknowns explicit. Narrower verified career evidence limits broad resume wording. Record new reusable answers here with exact source, date, scope and superseded value; do not create parallel personal-source files.

Historical workflow instructions and past sharing approvals are provenance, not current execution authority. Browser autofill, generated resumes and agent assumptions do not establish personal facts.

## Current answer index

Record verified contact/residence, work eligibility, education, availability, travel, relevant logistics, skills and durations. Leave unresolved fields explicitly unknown. Preserve sensitive demographic answers privately and use only applicable explicit approval.

## Career evidence

Keep detailed employment/project claims, dates, ownership, metrics, evidence boundaries and unresolved details. Do not invent experience, scale, degrees, or performance metrics. Do not embed a second copy of the master resume.

## Employer-specific previous answers

For each answer include employer/job, exact question, confirmed answer, original date, scope, as-of limits, and what it supersedes.

## Exact dated answer history and source provenance

Retain exact user wording and source references. Mark superseded material clearly and resolve active answers in the index. Archived original files are lossless recovery material, not active parallel profiles.
